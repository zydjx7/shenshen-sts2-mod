# 光之魔法少女深深：角色开发规格

## 已确定

- 为《杀戮尖塔 2》制作个人使用的原创人物模组。
- 角色显示名称暂定为「光之魔法少女深深」。
- 深深原本是一位少女魔法师，能够使用变形魔法变成专属的猫形态。
- 人形态与猫形态互斥；是同一角色的变形，不是少女和猫伙伴同时登场。
- 人形态以魔法、祝福和自我强化为主；猫形态以多段攻击及灵活防御为方向。
- 同一张「变形魔法」在人形、猫形均可使用，双向切换形态。每次消耗 1 点能量，结算后回到手牌；不额外设置每回合次数上限，能量足够就能再次使用。
- 每场战斗开始时，额外将 1 张「变形魔法」加入手牌，不占正常起手抽牌数量；这张牌回合结束时保留。
- 形态在回合之间延续；战斗结束后恢复少女，下一场战斗以少女形态开始。
- 变身保留当前生命、剩余能量、格挡，以及力量、敏捷、荆棘等增益和中毒、虚弱等负面状态。
- 两种形态使用不同卡牌；猫牌必须是本局实际拥有的牌，不从完整猫卡池中随意生成。
- 变身只更换当前形态的专属手牌。诅咒牌、无色牌和状态牌暂定保留在手中，不参与这次更换。
- 少女牌和猫牌分别维护抽牌、弃牌循环。正常抽牌从当前形态的牌组抽取；不足时洗入该形态的弃牌，仍不足则少抽，不额外生成牌。
- 猫形态每回合自动闪避敌方多段攻击中的一段；单段攻击无法闪避。反复变身不刷新本回合的闪避次数。「咪闪」本身只提供格挡。
- 同时支持单人与多人模式。「光之祝福」定位为较容易获得的多人专用牌，只能祝福其他队友，不能对自己使用。
- 在 macOS 与 Windows 上共用项目源码和素材，分别验证游戏内运行。
- 建议以 `Shenshen` 作为稳定内部 ID；显示名称后续可改，不必随之更换内部 ID 或项目目录名。

本文记录设计与验证目标，不表示角色或双形态已在游戏中实现。已确认的数值先用于原型；未确认的属性、剧情、升级效果和结算细节继续保留为待定。

## 用户提出的玩法方向

以下为用户描述的例子或暂定效果，不代表完整卡牌已设计或实现：

- 人形攻击可使用小火球等火焰魔法，防御牌可表现为光之护盾。
- 光之祝福：祝福其他队友，使其下回合可以从抽牌堆中选择一张牌加入手牌。不能对自己使用；作为多人专用牌，单人奖励不应出现。希望较容易获得，具体稀有度、费用、触发时机、是否额外抽取及重复施放规则待确认。
- 人形可用魔法提高自身力量、荆棘或敏捷；强化跨形态保留，具体数值、费用和持续时间待定。
- 基础猫攻击牌暂定为「爪击」：1 费，造成 3 点伤害两次，猫牌组初始 5 张。
- 猫基础防御牌暂定为「咪闪」：1 费，获得 6 点格挡，猫牌组初始 5 张，不附带额外闪避。
- 猫形被动的具体闪避段落与刷新时点、受击触发互动仍需在实现前明确。

## 卡牌来源与战斗奖励

已确认采用玩家实际拥有的两套形态牌组；原型起始少女牌组为 5 张小火球与 5 张光之护盾，猫牌组为 5 张爪击与 5 张咪闪。战斗后可以正常获得新猫牌。

暂定沿用普通战斗奖励方式，候选中可以混合出现少女牌和猫牌；多人专用牌需要按模式筛选。「展示三张少女牌与三张猫牌，合计六选一」保留为后续结合强度再评估的备选，不是当前已选规则。

## 变身时更换手牌

双向变身时，将当前形态的专属手牌弃掉，再从已拥有的目标形态牌组抽取相同数量；诅咒、无色牌、状态牌暂定留在手中。未参与更换的牌不计入本次补牌数量，「变形魔法」在结算后单独回手。

例如手中有「变形魔法」、3 张少女专属牌和 1 张诅咒：变成猫时弃掉 3 张少女牌、从猫牌组补抽 3 张，诅咒留在手中，变形魔法结算后回手。若目标牌组抽牌不足，先洗入目标形态的弃牌；仍不足则只抽实际可用的数量。

两套循环必须保留实际拥有的卡牌及其升级等状态，不能用临时生成同名牌代替。弃牌与抽牌触发、手牌上限、共享牌如何进入抽弃牌循环，以及保存和联机同步的细节待实现前核对。

## 本机实现参考

以下已只读核对本机游戏 `0.107.1`，是后续实现参考，不替代待确认的玩法规则：

- 多人牌可使用 `CardMultiplayerConstraint.MultiplayerOnly`；标准卡池会按模式过滤。自定义奖励也应保留该筛选。
- 原版 `BelieveInYou`、`Coordinate` 使用 `TargetType.AnyAlly`。祝福还应在效果端明确拒绝自身目标，不能仅依赖目标选择界面。
- `ForegoneConclusionPower.BeforeHandDraw` 可参考：在正常抽牌前，让目标玩家从抽牌堆选择牌加入手牌，然后移除该能力。这种入手不会触发普通抽牌的 `AfterCardDrawn`；光之祝福是否采用这一时机与触发方式仍待决定。

## 分阶段验证目标

1. **工程与角色入口**：两台电脑从同一份源码完成构建，游戏能加载模组；角色选择页出现名称与占位形象，可以开始一场测试战斗。
2. **双形态状态原型**：先确定最小切换规则；能明确显示人形态或猫形态，验证合法切换、无效切换，以及战斗边界的状态处理。此阶段不要求完整卡池或正式美术。
3. **最小玩法闭环**：加入基础牌、变形与猫形闪避，再用少量强化魔法验证跨形态配合；验证切换前后效果、资源与状态保持一致，并验证多人专用祝福的目标和选牌交互。
4. **保存与平台验证**：在专用测试档验证退出重进与恢复战斗；分别在 Mac 和 Windows 测试相同版本、相同场景，记录结果，不使用日常游玩存档做开发实验。
5. **内容与表现扩展**：核心循环稳定后再补充卡池、遗物、美术和动画；每次扩展保持两种形态可辨认，文字与实际效果一致。

每个阶段以可重复的游戏内操作和结果作为验收依据。尚未确定的设计先记录决定，再实现，避免把临时占位规则当成最终设定。
