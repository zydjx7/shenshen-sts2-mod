# 光之魔法少女深深：角色开发规格

## 已确定

- 为《杀戮尖塔 2》制作个人使用的原创人物模组。
- 角色显示名称暂定为「光之魔法少女深深」。
- 深深原本是一位少女魔法师，能够使用变形魔法变成专属的猫形态。
- 人形态与猫形态互斥；是同一角色的变形，不是少女和猫伙伴同时登场。
- 人形态以魔法、祝福和自我强化为主；猫形态以多段攻击及灵活防御为方向。
- 通过打出变身卡切换形态；费用、获得方式、次数限制和卡牌自身去向待定。
- 在 macOS 与 Windows 上共用项目源码和素材，分别验证游戏内运行。
- 建议以 `Shenshen` 作为稳定内部 ID；显示名称后续可改，不必随之更换内部 ID 或项目目录名。

本文记录设计与验证目标，不表示角色或双形态已在游戏中实现。具体属性、剧情、卡牌数值和完整结算规则尚未确定。

## 用户提出的玩法方向

以下为用户描述的例子或暂定效果，不代表完整卡牌已设计或实现：

- 人形攻击可使用小火球等火焰魔法，防御牌可表现为光之护盾。
- 光之祝福：祝福队友，使其下回合可以从抽牌堆中选择一张牌加入手牌。单人目标、具体触发时机和联机交互待确认。
- 人形可用魔法提高自身力量、荆棘或敏捷；这些强化是否跨形态保留仍需明确。
- 猫形可用爪击等多段攻击。
- 猫形暂定能闪避敌方多段攻击中的一段；触发条件、刷新频率和对单段攻击的处理待确认。

## 待确认方案：变身时更换手牌

用户提出：回合内打出变身卡后，将人形手牌全部弃掉，再抽取相同数量的猫形牌。反向切换是否对称，尚未明确。

该思路可以作为变身原型的设计方向，实施前先确认：

1. 猫牌来自本局实际拥有的猫牌组，还是从全部猫卡中随机生成。两者会影响选牌、升级、删牌及牌组循环的意义。
2. 更换范围是当前形态专属牌，还是包含无色牌、状态牌、诅咒的所有剩余手牌。

之后再明确换牌数量的计算时点（变身卡打出后的剩余手牌）、是否触发通常的弃牌与抽牌效果、抽牌不足时的洗牌处理，以及反向切换规则。本轮尚未替用户选择这些规则，也未修改战斗代码。

## 待确定

| 主题 | 需要决定的内容 |
| --- | --- |
| 形态切换 | 已选卡牌触发；消耗、次数、时机、变身卡自身去向及反向切换规则待定。 |
| 形态差异 | 人形魔法/强化、猫形多段攻击/灵活防御；具体效果与限制待定。 |
| 共享资源 | 生命、能量、格挡、状态和其他资源是否在两种形态之间共享。 |
| 卡池与起始配置 | 已提出两种形态使用不同卡牌并在变身时换手牌；牌的来源、牌堆循环、初始配置、遗物及属性待定。 |
| 状态延续 | 战斗开始、战斗结束、死亡、读档后保留哪种形态；如何处理已有状态。 |
| 显示与交互 | 如何显示当前形态和切换条件；无效切换时如何反馈。 |
| 美术与文字 | 两种形态的立绘、战斗形象、动画、图标、卡图和中文文本；先用占位素材验证流程。 |
| 兼容范围 | 首先验证单人模式；是否支持多人及其他模组组合另行决定。 |

## 分阶段验证目标

1. **工程与角色入口**：两台电脑从同一份源码完成构建，游戏能加载模组；角色选择页出现名称与占位形象，可以开始一场测试战斗。
2. **双形态状态原型**：先确定最小切换规则；能明确显示人形态或猫形态，验证合法切换、无效切换，以及战斗边界的状态处理。此阶段不要求完整卡池或正式美术。
3. **最小玩法闭环**：在确定形态差异后，只加入足以验证核心机制的少量卡牌或效果；验证切换前后效果、资源与状态保持一致。
4. **保存与平台验证**：在专用测试档验证退出重进与恢复战斗；分别在 Mac 和 Windows 测试相同版本、相同场景，记录结果，不使用日常游玩存档做开发实验。
5. **内容与表现扩展**：核心循环稳定后再补充卡池、遗物、美术和动画；每次扩展保持两种形态可辨认，文字与实际效果一致。

每个阶段以可重复的游戏内操作和结果作为验收依据。尚未确定的设计先记录决定，再实现，避免把临时占位规则当成最终设定。
