# 光之魔法少女深深：角色开发规格

## 已确定

- 为《杀戮尖塔 2》制作个人使用的原创人物模组。
- 角色显示名称暂定为「光之魔法少女深深」。
- 角色有「人形态」与「猫形态」。
- 在 macOS 与 Windows 上共用项目源码和素材，分别验证游戏内运行。
- 建议以 `Shenshen` 作为稳定内部 ID；显示名称后续可改，不必随之更换内部 ID 或项目目录名。

本文记录设计与验证目标，不表示角色或双形态已在游戏中实现。具体属性、剧情、卡牌和技能效果尚未确定。

## 待确定

| 主题 | 需要决定的内容 |
| --- | --- |
| 形态切换 | 通过主动按钮、卡牌还是条件触发；是否有消耗、次数限制和切换时机。 |
| 形态差异 | 两种形态各自承担什么玩法作用；哪些效果仅在某种形态生效。 |
| 共享资源 | 生命、能量、格挡、状态和其他资源是否在两种形态之间共享。 |
| 卡池与起始配置 | 两种形态共用卡池还是有形态限定牌；初始牌组、遗物及属性待定。 |
| 状态延续 | 战斗开始、战斗结束、死亡、读档后保留哪种形态；如何处理已有状态。 |
| 显示与交互 | 如何显示当前形态和切换条件；无效切换时如何反馈。 |
| 美术与文字 | 两种形态的立绘、战斗形象、动画、图标、卡图和中文文本；先用占位素材验证流程。 |
| 兼容范围 | 首先验证单人模式；是否支持多人及其他模组组合另行决定。 |

## 分阶段验证目标

1. **工程与角色入口**：两台电脑从同一份源码完成构建，游戏能加载模组；角色选择页出现名称与占位形象，可以开始一场测试战斗。
2. **双形态状态原型**：先确定最小切换规则；能明确显示人形态或猫形态，验证合法切换、无效切换，以及战斗边界的状态处理。此阶段不要求完整卡池或正式美术。
3. **最小玩法闭环**：在确定形态差异后，只加入足以验证核心机制的少量卡牌或效果；验证切换前后效果、资源与状态保持一致。
4. **保存与平台验证**：在专用测试档验证退出重进与恢复战斗；分别在 Mac 和 Windows 测试相同版本、相同场景，记录结果，不使用日常游玩存档做开发实验。
5. **内容与表现扩展**：核心循环稳定后再补充卡池、遗物、美术和动画；每次扩展保持两种形态可辨认，文字与实际效果一致。

每个阶段以可重复的游戏内操作和结果作为验收依据。尚未确定的设计先记录决定，再实现，避免把临时占位规则当成最终设定。
