## 动画接入

以本机游戏 0.111.0 和锁定 BaseLib 3.4.7 实际程序集为依据。原版 `CreatureAnimator` 依赖 Spine；本项目不冒充 Spine 骨架，使用 BaseLib 已有的非 Spine `CustomAnimation` 桥接，通过原生 Godot `AnimationPlayer` 驱动多个 Sprite2D 分件。

`ShenshenVisuals` 构造 `NCreatureVisuals` 所需 Bounds、中心、意图和特效节点，按 JSON 清单的父子关系、枢轴与 AtlasTexture 区域装配。图集中的多个矩形区域只是取材范围，透明背景由 PNG alpha 保留；不按预览器中残留 RGB 背景判断是否透明。

- Idle：躯干轻微呼吸、头部与马尾、披风和袖臂独立运动，睁闭眼切换。
- Attack：持杖手臂与上身动作，法杖跟随手臂，攻击延迟与角色的 `AttackAnimDelay` 对齐。
- Cast / PowerUp：施法手势和局部光效；非攻击技能显式发出 Cast 事件，不更改卡牌数值与牌堆。
- Hit：受击后仰与短暂闭眼；Dead：倒下并停在末帧；Revive 回到待机。
- BaseLib 不替非 Spine 场景初始化待机或自动返回待机。本控制器在 Ready 启动 Idle，单次动作结束后回返，死亡动作除外。死亡等待使用角色的 `DeathAnimTime`。
- 形态外观由实际 FormPower 决定；换形只切换视觉容器，不复制战斗模型、卡牌或状态。

`rig.json` 的 z 只表示角色内部顺序，通过兄弟节点排列实现；实际 CanvasItem 的 Z 保持 0，统一继承战斗角色层。不能把负 z 直接写到 Sprite2D：本机战斗场景为 -10、前景特效为 -9，直接写入会让腿/披风沉到背景后，正 z 又会让头部越过暂停遮罩。该问题已在实际游戏中复现并修复。

选人背景、头像、选人按钮和地图标记是独立资源，不能仅替换战斗形象后就认为所有入口都已更新。原游戏选人按钮和地图标记 getter 要求 CompressedTexture2D；BaseLib 只替换路径，不能给这些路径返回 AtlasTexture。头像 `avatar.png` 和 2:3 选人按钮 `select-icon.png` 现从同一动画头部原像素导出为 PNG，使用透明留白适配画布；自建选人背景的普通 Control 场景直接使用头部 AtlasTexture 与去旧头的身体底图。战斗分件内部也可使用 AtlasTexture，不受上述 UI getter 限制。
